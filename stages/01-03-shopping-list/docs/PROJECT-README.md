## 1. Оригинальное требование и перевод

Формулировка со скриншота:

> Create a simple shopping list app.
>
> User can type shopping items and when the button is pressed, the new typed
> item is added to the list. Clear button removes all items from the list.

Точный перевод:

> Создайте простое приложение со списком покупок. Пользователь может вводить
> товары. После нажатия кнопки новый введённый товар добавляется в список.
> Кнопка Clear удаляет из списка все товары.

Ввод нужно обрезать по краям, пустые названия запрещены, одинаковые названия разрешены, список выводится через `FlatList`, а данные существуют только до полного перезапуска.

## 2. Реализованные критерии

- видимая подпись `Shopping item`, placeholder `Enter an item` и доступная метка;
- кнопки `ADD` и `CLEAR`;
- строка `  Milk  ` превращается в `Milk`, после добавления поле очищается;
- пробельная строка показывает `Enter an item name.` и не добавляется;
- два ввода `Milk` создают две отдельные строки с id `item-1` и `item-2`;
- `CLEAR` создаёт новый пустой массив и показывает `No items yet.`;
- покупки не сохраняются в AsyncStorage или на сервере.

## 3. Требования к среде

- Node.js `>=20.19.4`; проект проверен на Node `v24.19.0`;
- Expo SDK 54, React 19.1.0, React Native 0.81.5;
- npm и доступ к npm registry для установки по lock-файлу;
- Android Studio и AVD `pixel_7_-_api_35_0` либо совместимое устройство;
- Expo Go с поддержкой SDK 54.

В PowerShell перед работой проверьте версии и пути:

```powershell
node --version
npm --version
Get-Command node,npm | Select-Object Name,Source
```

`node --version` должен быть не ниже `v20.19.4`, а пути `node` и `npm` на
Windows должны относиться к одной установленной версии Node.js. Если видна
версия `v20.11.1` либо пути ведут в разные установки, обновите системный
Node.js, полностью закройте терминалы VS Code и откройте VS Code заново.
Простого изменения `Path` недостаточно, если `npm.cmd` всё ещё запускает
соседний старый `node.exe`.

## 6. Состояние, события и поток данных

`itemInput` хранит текущий текст. `items` — массив объектов `{ id, name }`. `errorMessage` хранит понятную ошибку, а `nextItemIdRef` выдаёт следующий id без отдельного рендера.

Поток добавления: `onChangeText` обновляет строку → `ADD` вызывает `handleAdd` → чистая функция нормализует имя → при ошибке список не меняется → при успехе создаётся новый массив и новый id → setter вызывает рендер → `FlatList` показывает строки. `CLEAR` заменяет список новым пустым массивом.

## 7. Разбор App.js и чистой логики

`App.js` связывает контролируемое поле и кнопки со state. `handleAdd` передаёт текущий массив, id и текст в чистую функцию. Счётчик увеличивается только при успехе. После успеха поле и ошибка очищаются. `keyExtractor` возвращает `item.id`, поэтому одинаковые названия безопасны.

В `src/shopping-list.js`:

- `normalizeItemName` применяет `trim()` и возвращает либо нормализованное имя, либо ошибку;
- `addShoppingItem` вызывает нормализацию и использует `[...items, newItem]`;
- `clearShoppingItems` каждый раз возвращает новый пустой массив.

Чистые функции не знают о React Native и проверяются обычным Jest без эмулятора.

## 8. React и React Native понятия

- **state** хранит меняющиеся данные экрана;
- **useState** возвращает значение и setter, который планирует повторный рендер;
- **useRef** хранит невидимый счётчик id между рендерами;
- **controlled input** означает, что `TextInput.value` всегда берётся из `itemInput`;
- **event handler** — функция, переданная в `onPress` или `onChangeText`;
- **immutable update** создаёт новый массив через spread, не выполняя `push` в state;
- **FlatList** получает `data`, `renderItem` и `keyExtractor`;
- **stable key** связывает строку с одной сущностью при следующих рендерах;
- **accessibilityLabel** делает назначение элемента доступным для экранного диктора и теста.

## 10. Ручной приёмочный чек-лист

1. При старте виден `No items yet.`.
2. Ввести `  Milk  ` и нажать `ADD`: отображается `Milk`, поле становится пустым.
3. Ещё раз добавить `Milk`: видны две отдельные строки `Milk`, предупреждения о повторном ключе нет.
4. Ввести только пробелы: появляется `Enter an item name.`, число строк не меняется.
5. Добавить ещё два товара, чтобы всего стало четыре.
6. Нажать `CLEAR`: все четыре строки исчезают, снова виден `No items yet.`.
7. Добавить товар, полностью остановить и перезапустить приложение: список снова пуст.

Ручную проверку выполняют на AVD `pixel_7_-_api_35_0`; автоматический export не подтверждает нажатия пользователя.

## 11. Диагностика типичных ошибок

- **Node ниже 20.19.4:** обновите системный Node.js и перезапустите терминал и VS Code; затем повторите обе команды проверки из раздела 3.
- **adb не видит устройство:** запустите AVD, дождитесь загрузки и проверьте `adb devices`.
- **Порт Metro занят:** остановите предыдущий процесс или подтвердите предложенный свободный порт.
- **Metro показывает старый код:** выполните `npx expo start --clear`.
- **Expo Go несовместим с SDK:** установите версию, поддерживающую Expo SDK 54.
- **После `a` приложение не открылось:** проверьте статус AVD/adb, затем повторите `a` после запуска Metro.

Ошибки в решении: `if (!text)` пропускает строку из пробелов; `items.push(...)` меняет существующий state; `item.name` и индекс не являются подходящими ключами; очистка только поля ввода не очищает список.

## 12. Вопросы преподавателя

1. Что делает поле управляемым?
2. Почему используется `trim()`?
3. Почему `[...items, item]` лучше `items.push(item)` для state?
4. Зачем `keyExtractor`, если текст уже виден?
5. Почему `item.name` нельзя использовать как единственный ключ?
6. Почему `nextItemIdRef` увеличивается только после успешной проверки?
7. Где хранится список и что произойдёт после перезапуска?

## 13. Краткие ответы

1. Его `value` приходит из state, а `onChangeText` обновляет тот же state.
2. Он убирает внешние пробелы и позволяет распознать пробельную строку как пустую.
3. Spread создаёт новую ссылку массива, и React надёжно видит изменение.
4. Ключ помогает React сопоставить элементы списка между рендерами.
5. Два допустимых товара `Milk` имеют одно имя, но должны иметь разные стабильные ключи.
6. Ошибка не должна расходовать id или менять данные.
7. Список находится в памяти компонента, поэтому полный перезапуск его очищает.

## 14. Английские формулировки для защиты

- `The TextInput is controlled by React state.`
- `I trim outer whitespace before I add an item.`
- `I create a new array with the spread operator.`
- `FlatList renders the shopping items.`
- `Duplicate names are allowed, so every row has a separate stable id.`
- `A blank value shows an error and does not change the list.`
- `I keep the list in memory, so restarting the app clears it.`

## 15. Необязательные самостоятельные улучшения

После защиты обязательной версии можно добавить удаление отдельного товара, отметку «куплено», количество или сортировку. Каждое улучшение требует нового падающего теста до изменения логики. Постоянное хранение, навигация, авторизация и сервер не входят в обязательное задание.
