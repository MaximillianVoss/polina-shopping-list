# Описание проекта «Shopping List»

## 1. Карточка проекта

| Поле | Значение |
|---|---|
| Учебный проект | № 03 — `Shopping List` |
| Назначение | Добавление названий покупок и полная очистка списка |
| Тип приложения | Одноэкранное мобильное приложение с хранением данных в памяти текущего сеанса |
| Основной интерфейс | React Native |
| Среда запуска | Expo SDK 54 (`expo ~54.0.36`) |
| Версии интерфейсного стека | React 19.1.0, React Native 0.81.5 |
| Минимальная версия Node.js | `20.19.4` |
| Точка входа интерфейса | `App.js` |
| Чистая предметная логика | `src/shopping-list.js` |
| Автоматические проверки | Jest, `jest-expo`, React Native Testing Library |
| Язык интерфейса | Английский |
| Постоянное хранение | Не используется: после полного перезапуска список снова пуст |

Проект демонстрирует небольшой, но законченный цикл работы с данными: пользователь вводит название, приложение проверяет строку, создаёт элемент с уникальным идентификатором, обновляет массив без мутации и отображает результат через `FlatList`.

## 2. Условие задания и перевод

**Оригинальное условие со скриншота:**

> Create a simple shopping list app.
>
> User can type shopping items and when the button is pressed, the new typed
> item is added to the list. Clear button removes all items from the list.

**Точный перевод:**

> Создайте простое приложение со списком покупок.
>
> Пользователь может вводить товары. После нажатия кнопки новый введённый
> товар добавляется в список. Кнопка Clear удаляет из списка все товары.

В реализованной версии условие конкретизировано следующими правилами:

- внешние пробелы удаляются: строка `"  Milk  "` сохраняется как `"Milk"`;
- пустая или состоящая только из пробелов строка не добавляется;
- при недопустимом вводе показывается сообщение `Enter an item name.`;
- одинаковые названия разрешены и получают разные стабильные `id`;
- порядок элементов совпадает с порядком успешного добавления;
- весь список выводится компонентом `FlatList`;
- кнопка `CLEAR` удаляет все элементы сразу;
- данные не записываются в `AsyncStorage`, файл или удалённый сервис.

## 3. Планируемые результаты обучения

После изучения и защиты проекта ученица сможет:

1. Объяснить разницу между состоянием интерфейса, ссылкой `useRef` и обычной локальной переменной.
2. Создать управляемый `TextInput`, связав `value={itemInput}` и `onChangeText={setItemInput}`.
3. Обработать нажатия `ADD` и `CLEAR` через функции `handleAdd` и `handleClear`.
4. Проверить строку после `trim()` и не допустить добавление пустого значения.
5. Обновить массив иммутабельно с помощью `[...items, newItem]`.
6. Отобразить массив объектов через `FlatList`, `renderItem` и `keyExtractor`.
7. Обосновать, почему `item.id` подходит для ключа, а `item.name` и индекс — нет.
8. Разделить компонентный код и чистую предметную логику.
9. Прочитать тест и связать пользовательское действие с ожидаемым состоянием интерфейса.
10. Провести ручную приёмку на Android или iOS и кратко представить решение на русском и английском языках.

Результат считается измеримым, если ученица без подсказки проводит основной сценарий, называет три состояния `itemInput`, `items`, `errorMessage`, объясняет роль `nextItemIdRef` и получает успешный результат автоматических тестов.

## 4. Функциональные критерии готовности

| № | Критерий | Наблюдаемый результат |
|---:|---|---|
| 1 | Начальное состояние | Видны заголовок `Shopping List`, поле и сообщение `No items yet.` |
| 2 | Ввод текста | Введённая строка хранится в `itemInput` и отображается в `TextInput` |
| 3 | Нормализация | Ввод `  Milk  ` добавляет строку `Milk` |
| 4 | Успешное добавление | Новый объект добавляется в конец `items`, поле очищается, ошибка очищается |
| 5 | Пустой ввод | Ввод `''` или только пробелов не меняет `items` и показывает `Enter an item name.` |
| 6 | Дубликаты | Два ввода `Milk` создают две строки с разными `id` |
| 7 | Порядок | Последовательность `Milk`, `Bread`, `Milk` отображается в том же порядке |
| 8 | Стабильные ключи | `keyExtractor={getShoppingItemKey}` возвращает `item-1`, `item-2`, `item-3`, … |
| 9 | Полная очистка | `CLEAR` заменяет список новым пустым массивом и убирает сообщение об ошибке |
| 10 | Пустой список | После очистки снова отображается `No items yet.` |
| 11 | Сеансовое хранение | Полный перезапуск приложения сбрасывает список |
| 12 | Доступность | Поле имеет `accessibilityLabel="Shopping item"`, список — `Shopping items`, пустое состояние — `Empty list message` |
| 13 | Живое сообщение | Текст ошибки имеет `accessibilityLiveRegion="polite"` и `testID="error-message"` |

Важно: текущий `handleClear` не очищает `itemInput` и не сбрасывает `nextItemIdRef`. Это фактическое поведение, а не дефект относительно исходного условия: кнопка отвечает именно за список и сообщение об ошибке.

## 6. Архитектура и ответственности

Решение состоит из двух уровней.

### Уровень интерфейса — `App.js`

- хранит изменяемые данные экрана;
- связывает данные с `TextInput`, текстами и `FlatList`;
- принимает события `onChangeText` и `onPress`;
- вызывает чистые функции предметной области;
- выбирает между пустым состоянием и списком;
- задаёт подписи доступности и стили.

### Уровень предметной логики — `src/shopping-list.js`

- `normalizeItemName(text)` удаляет внешние пробелы и проверяет пустоту;
- `addShoppingItem(items, id, text)` создаёт новый объект и новый массив;
- `getShoppingItemKey(item)` возвращает стабильный идентификатор;
- `clearShoppingItems()` возвращает новый пустой массив.

Чистые функции не импортируют React или React Native, не читают состояние компонента и не меняют переданный массив. Поэтому их можно проверять быстрыми unit-тестами. `App.js` отвечает за координацию: он передаёт функциям текущие значения и применяет результат через setter-функции.

## 7. Модель состояния

| Имя | Создание | Тип и начальное значение | Что хранит | Что изменяет |
|---|---|---|---|---|
| `itemInput` | `useState('')` | строка, `''` | Текущий видимый текст поля | `setItemInput` из `onChangeText`; успешный `handleAdd` |
| `items` | `useState([])` | массив, `[]` | Объекты `{ id, name }` в порядке добавления | `setItems` в `handleAdd` и `handleClear` |
| `errorMessage` | `useState('')` | строка, `''` | Текст текущей ошибки или пустая строка | `setErrorMessage` в обоих обработчиках |
| `nextItemIdRef.current` | `useRef(1)` | число, `1` | Номер следующего успешного элемента | Увеличение на `1` только после успешной проверки |

Инварианты модели:

- каждый объект в `items` имеет строковые поля в форме `{ id: 'item-N', name: '...' }`;
- `name` после успешного добавления не пуст и не содержит внешних пробелов;
- допустимые одинаковые `name` имеют разные `id`;
- неуспешное добавление не меняет `items`, `itemInput` и `nextItemIdRef.current`;
- `errorMessage` равен либо `''`, либо точной строке `Enter an item name.`;
- setter состояния вызывает новый рендер, а изменение `.current` у `useRef` само по себе рендер не вызывает.

## 8. Поток данных и событий

### Добавление

1. Пользователь вводит символы в поле.
2. `TextInput` вызывает `onChangeText` с новой строкой.
3. `setItemInput` записывает строку в `itemInput`.
4. Пользователь нажимает `ADD`.
5. `Button` вызывает `handleAdd`.
6. `handleAdd` передаёт `items`, строку ``item-${nextItemIdRef.current}`` и `itemInput` в `addShoppingItem`.
7. Чистая функция вызывает `normalizeItemName`.
8. При ошибке `setErrorMessage(addition.error)` показывает `Enter an item name.`, затем ранний `return` прекращает обработку.
9. При успехе счётчик увеличивается, `setItems(addition.items)` применяет новый массив, `setItemInput('')` очищает поле, `setErrorMessage('')` очищает ошибку.
10. После рендера `items.length > 0`, поэтому вместо пустого сообщения создаётся `FlatList`.

### Очистка

1. Пользователь нажимает `CLEAR`.
2. `handleClear` получает новый массив от `clearShoppingItems()`.
3. `setItems(...)` заменяет прежний список.
4. `setErrorMessage('')` убирает ошибку.
5. После рендера условие `items.length === 0` показывает `No items yet.`.

### Полный перезапуск

Компонент создаётся заново: `itemInput`, `items` и `errorMessage` получают начальные значения, а `nextItemIdRef.current` снова равен `1`. Поскольку постоянное хранилище не используется, предыдущие покупки не восстанавливаются.

## 9. Основные алгоритмы

### Нормализация имени

`normalizeItemName(text)` вычисляет `const name = text.trim()`. Если `name === ''`, функция возвращает `{ ok: false, error: 'Enter an item name.' }`; иначе возвращает `{ ok: true, name }`. Проверка выполняется после `trim()`, поэтому строки `''`, `'   '` и сочетания пробелов по краям обрабатываются правильно.

### Иммутабельное добавление

`addShoppingItem(items, id, text)` сначала проверяет имя. При ошибке функция сразу возвращает объект ошибки. При успехе выражение `[...items, { id, name: normalized.name }]` копирует ссылки на существующие элементы в новый массив и добавляет новый объект в конец. Исходный массив остаётся неизменным.

### Формирование идентификатора

`handleAdd` формирует идентификатор из значения `nextItemIdRef.current`: сначала `item-1`, затем `item-2` и так далее. Счётчик увеличивается только после результата `ok: true`, поэтому неуспешная попытка не создаёт пропуск в последовательности.

### Извлечение ключа

`getShoppingItemKey(item)` возвращает `item.id`. Название не подходит, потому что дубликаты разрешены. Индекс не подходит как идентичность сущности: он зависит от положения элемента, а не от самого элемента.

### Полная очистка

`clearShoppingItems()` каждый раз возвращает литерал `[]`. Тест дополнительно подтверждает, что два вызова дают два разных объекта массива. Это согласуется с иммутабельной моделью обновления состояния.

## 10. Валидация и обработка ошибок

| Ввод или действие | Результат функции | Изменение интерфейса |
|---|---|---|
| `'Milk'` | `{ ok: true, name: 'Milk' }` | Добавляется `Milk`, поле очищается |
| `'  Milk  '` | `{ ok: true, name: 'Milk' }` | Добавляется нормализованное имя |
| `''` | `{ ok: false, error: 'Enter an item name.' }` | Список не меняется, показывается ошибка |
| `'   '` | `{ ok: false, error: 'Enter an item name.' }` | Список не меняется, показывается ошибка |
| Повторное `'Milk'` | Успех с новым `id` | Появляется ещё одна строка `Milk` |
| `CLEAR` | Новый `[]` | Все строки и ошибка исчезают |

Ошибка размещена в постоянно существующем компоненте `Text`:

```jsx
<Text accessibilityLiveRegion="polite" style={styles.error} testID="error-message">
  {errorMessage}
</Text>
```

`accessibilityLiveRegion="polite"` просит Android сообщать изменение без грубого прерывания текущей речи. `testID="error-message"` даёт тесту стабильную точку поиска. У текста намеренно нет `accessibilityLabel`: экранный диктор должен прочитать фактическое содержимое `Enter an item name.`, а тест отдельно закрепляет отсутствие переопределяющей метки.

Текущая реализация не очищает ошибку при простом изменении текста после неуспешной попытки. Ошибка исчезает после следующего успешного `ADD` или после `CLEAR`. Это следует учитывать при ручной приёмке и не приписывать приложению валидацию «на каждом символе».

## 11. Запуск с нуля на Windows/Android и macOS/iOS

### Общие требования

- Node.js версии `20.19.4` или новее;
- npm, поставляемый вместе с совместимой версией Node.js;
- доступ к npm registry для `npm ci`;
- Expo SDK 54 уже указан зависимостью проекта;
- для физического устройства — совместимая с SDK 54 версия Expo Go и одна локальная сеть с компьютером.

Проверка среды на обеих платформах:

```text
node --version
npm --version
```

Версия Node.js должна быть не ниже `v20.19.4`.

### Windows + Android

1. Установить Node.js подходящей версии.
2. Установить Android Studio, Android SDK и создать виртуальное устройство либо включить режим разработчика и USB-отладку на физическом Android-устройстве.
3. Открыть PowerShell в корне проекта.
4. Установить строго зафиксированные зависимости и запустить Metro:

```powershell
npm ci
npx expo start
```

5. Дождаться загрузки Android Emulator и нажать `a` в терминале Metro. Альтернативная команда запуска — `npm run android`.
6. Для физического устройства открыть Expo Go и считать QR-код из терминала.
7. Остановить Metro сочетанием `Ctrl+C`.

Если Metro использует устаревший кеш, выполнить:

```powershell
npx expo start --clear
```

### macOS + iOS

1. Установить Node.js подходящей версии.
2. Установить Xcode, принять лицензию и один раз открыть iOS Simulator. Для managed-проекта Expo отдельная ручная установка CocoaPods для обычного запуска через Expo Go не требуется.
3. Открыть Terminal в корне проекта.
4. Установить зависимости и запустить Metro:

```bash
npm ci
npx expo start
```

5. Нажать `i`, чтобы открыть проект в iOS Simulator. Альтернативная команда — `npm run ios`.
6. На физическом iPhone можно открыть совместимую версию Expo Go и считать QR-код.
7. Остановить Metro сочетанием `Control+C`.

Windows не предоставляет локальный iOS Simulator: для сценария iOS нужен macOS с Xcode или физическое устройство с поддерживаемым способом запуска.

## 12. Тестирование и приёмка

### Автоматические проверки

Из корня проекта:

```text
npm ci
npm test -- --runInBand
npx expo-doctor
```

`__tests__/shopping-list.test.js` проверяет:

- добавление дубликатов с разными `id`;
- сохранение исходного массива без мутации;
- стабильный ключ `item.id`;
- возврат нового пустого массива при каждой очистке.

`__tests__/App.test.js` проверяет:

- ввод через доступную метку `Shopping item`;
- нажатия кнопок с именами `ADD` и `CLEAR`;
- очистку поля после успешного добавления;
- появление `Milk` и доступного списка `Shopping items`;
- точную ошибку в `error-message` и отсутствие у неё `accessibilityLabel`;
- возврат `Empty list message` с текстом `No items yet.`;
- порядок `Milk`, `Bread`, `Milk`;
- ключи `item-1`, `item-2`, `item-3`;
- две отдельные строки с одинаковым текстом `Milk`.

### Ручная приёмка

1. Запустить приложение: увидеть `No items yet.`.
2. Ввести `  Milk  `, нажать `ADD`: увидеть `Milk`, пустое поле и отсутствие ошибки.
3. Ещё раз добавить `Milk`: увидеть две строки `Milk` без предупреждения о повторяющемся ключе.
4. Ввести `Bread`: убедиться, что он появился после двух предыдущих строк.
5. Ввести только пробелы и нажать `ADD`: увидеть `Enter an item name.`, а список оставить без изменений.
6. Нажать `CLEAR`: увидеть `No items yet.` и пустую область ошибки.
7. До очистки ввести непустой текст и убедиться, что `CLEAR` не очищает само поле — это текущее поведение.
8. Добавить товар, полностью завершить приложение и открыть заново: список должен быть пуст.

## 13. Ограничения и границы решения

- Список существует только в памяти текущего экземпляра компонента.
- Нет сохранения в `AsyncStorage`, базу данных, файл или сервер.
- Нет удаления, редактирования или отметки отдельного элемента.
- Нет количества, цены, категории, сортировки и поиска.
- Дубликаты не объединяются и не считаются ошибкой.
- `CLEAR` не запрашивает подтверждение.
- `CLEAR` не очищает `itemInput` и не возвращает счётчик к `1` в рамках текущего монтирования.
- Ошибка проверяется при `ADD`, а не при каждом изменении текста.
- Поле ошибки не локализовано и содержит только английскую строку.
- Разметка рассчитана на один экран шириной не более `420` условных пикселей; отдельной планшетной композиции нет.
- Верхний отступ задан стилем `paddingTop: 36`, а не вычисляется через API безопасной области.
- Автоматические тесты не заменяют проверку реального экранного диктора и поведения клавиатуры на устройстве.

Эти ограничения соответствуют учебному объёму. Расширения следует вводить отдельными требованиями и тестами, а не менять смысл базового задания во время защиты.

## 14. Подготовка к защите на русском и английском
