# Методическое руководство к проекту «Shopping List»

## 1. Аудитория и предварительные знания

Руководство рассчитано на индивидуальное 90-минутное занятие с ученицей, которая уже знакома с основами JavaScript, но только осваивает React Native. Проект подходит для подготовки к практической демонстрации и устной защите.

До занятия ученица должна уметь:

- объявлять `const` и `function`;
- работать со строками, массивами и объектами;
- понимать параметры, аргументы и возвращаемое значение функции;
- читать условие `if` и ранний `return`;
- использовать шаблонную строку и оператор spread;
- в общих чертах понимать JSX и импорт модулей;
- выполнять команды в PowerShell или Terminal;
- различать редактирование файла и запуск программы.

Не требуется заранее знать `FlatList`, `useRef`, React Native Testing Library или устройство Expo-проекта: эти понятия вводятся на занятии. Предварительная установка Node.js и эмулятора желательна, чтобы учебное время не ушло на загрузку больших компонентов Android Studio или Xcode.

## 2. Измеримые цели занятия

К концу 90 минут ученица должна без подсказки:

1. Перевести исходное условие и перечислить не менее пяти критериев приёмки.
2. Назвать назначения `itemInput`, `items`, `errorMessage` и `nextItemIdRef`.
3. Проследить путь данных от `onChangeText` до строки внутри `FlatList`.
4. Объяснить, почему строка из пробелов отклоняется только после `trim()`.
5. Показать, где создаётся новый массив, и доказать, что исходный массив не мутируется.
6. Объяснить, почему дубликаты `Milk` получают разные ключи.
7. Провести сценарии «успешное добавление», «ошибка», «дубликат» и «очистка».
8. Соотнести хотя бы четыре действия теста с видимым поведением приложения.
9. Ответить минимум на 8 из 10 вопросов рубрики защиты.
10. Сформулировать на английском не менее пяти технически точных предложений о решении.

Успех занятия подтверждается тремя источниками: автоматические тесты проходят; ручной чек-лист выполнен; объяснение ученицы набирает не менее 7 из 10 баллов по рубрике раздела 13.

## 7. Пошаговое программирование решения

Этот раздел описывает безопасную последовательность создания текущей реализации. На каждом шаге сначала формулируется ожидаемое поведение, затем вводится минимальный код, затем выполняется проверка.

### Шаг 1. Задать модель одного элемента

Элемент имеет форму:

```js
{ id: 'item-1', name: 'Milk' }
```

`name` виден пользователю, а `id` используется как стабильная техническая идентичность. Два объекта могут иметь одинаковый `name`, но не должны иметь одинаковый `id`.

### Шаг 2. Реализовать нормализацию

```js
export function normalizeItemName(text) {
  const name = text.trim();
  return name === '' ? { ok: false, error: 'Enter an item name.' } : { ok: true, name };
}
```

Проверки до следующего шага: `"  Milk  "` превращается в `Milk`; `"   "` даёт точную ошибку.

### Шаг 3. Реализовать иммутабельное добавление

```js
export function addShoppingItem(items, id, text) {
  const normalized = normalizeItemName(text);
  if (!normalized.ok) return normalized;
  return { ok: true, items: [...items, { id, name: normalized.name }] };
}
```

Переданный `items` не меняется. Ошибка возвращается без поля `items`, поэтому вызывающий код обязан проверить `ok` до чтения `addition.items`.

### Шаг 4. Добавить ключ и полную очистку

```js
export function getShoppingItemKey(item) {
  return item.id;
}

export function clearShoppingItems() {
  return [];
}
```

Два вызова `clearShoppingItems()` дают равные по содержимому, но разные по ссылке массивы.

### Шаг 5. Создать состояния и ссылку

Создать `App.js` и сначала вставить фактические импорты проекта:

```js
import { StatusBar } from 'expo-status-bar';
import { useRef, useState } from 'react';
import { Button, FlatList, StyleSheet, Text, TextInput, View } from 'react-native';
import {
  addShoppingItem,
  clearShoppingItems,
  getShoppingItemKey,
} from './src/shopping-list';
```

После импортов объявить `export default function App() { ... }` и разместить
следующие строки в начале тела компонента:

```js
const [itemInput, setItemInput] = useState('');
const [items, setItems] = useState([]);
const [errorMessage, setErrorMessage] = useState('');
const nextItemIdRef = useRef(1);
```

До добавления интерфейса ученица должна назвать тип каждого начального значения.

### Шаг 6. Связать поле со state

```jsx
<TextInput
  accessibilityLabel="Shopping item"
  keyboardType="default"
  onChangeText={setItemInput}
  placeholder="Enter an item"
  placeholderTextColor="#64748b"
  style={styles.input}
  value={itemInput}
/>
```

Критическая пара — `value` и `onChangeText`. Если оставить только `value`, поле станет недоступным для нормального редактирования; если убрать `value`, оно перестанет быть управляемым текущим state.

### Шаг 7. Реализовать `handleAdd`

```js
function handleAdd() {
  const addition = addShoppingItem(items, `item-${nextItemIdRef.current}`, itemInput);
  if (!addition.ok) {
    setErrorMessage(addition.error);
    return;
  }

  nextItemIdRef.current += 1;
  setItems(addition.items);
  setItemInput('');
  setErrorMessage('');
}
```

Последовательность принципиальна: результат проверяется до увеличения счётчика и до чтения `addition.items`.

### Шаг 8. Подключить кнопку `ADD`

```jsx
<Button title="ADD" onPress={handleAdd} color="#2563eb" />
```

Передаётся ссылка на функцию `handleAdd`. Вариант `onPress={handleAdd()}` вызвал бы её во время рендера.

### Шаг 9. Вывести ошибку

```jsx
<Text accessibilityLiveRegion="polite" style={styles.error} testID="error-message">
  {errorMessage}
</Text>
```

Компонент остаётся в дереве даже при пустой строке, а `minHeight: 20` уменьшает скачок компоновки.

### Шаг 10. Вывести пустое состояние или `FlatList`

```jsx
{items.length === 0 ? (
  <Text accessibilityLabel="Empty list message" style={styles.emptyText}>
    No items yet.
  </Text>
) : (
  <FlatList
    accessibilityLabel="Shopping items"
    contentContainerStyle={styles.listContent}
    data={items}
    keyExtractor={getShoppingItemKey}
    renderItem={({ item }) => <Text style={styles.item}>{item.name}</Text>}
  />
)}
```

Условие предотвращает показ пустого списка без пояснения. `renderItem` показывает `name`, а `keyExtractor` использует `id`.

### Шаг 11. Реализовать очистку

```js
function handleClear() {
  setItems(clearShoppingItems());
  setErrorMessage('');
}
```

```jsx
<Button title="CLEAR" onPress={handleClear} color="#475569" />
```

Проверка должна учитывать точную ответственность: список и ошибка очищаются; поле и следующий номер не сбрасываются.

### Шаг 12. Проверить стили и платформы

`StyleSheet.create` группирует именованные объекты стилей. Необходимо визуально проверить ширину карточки, читаемость текста, контраст ошибки, прокрутку длинного списка, Android-клавиатуру и iOS-клавиатуру.

## 8. Разбор текущего кода

### Импорты

`StatusBar` приходит из `expo-status-bar`; `useState` и `useRef` — из React; визуальные компоненты и `StyleSheet` — из `react-native`; четыре функции предметной логики импортируются из локального модуля.

### `App`

`App` — функциональный компонент и владелец состояния экрана. При изменении `itemInput`, `items` или `errorMessage` React снова вызывает компонент и строит новое описание интерфейса. Значение `nextItemIdRef.current` сохраняется, но его изменение не является причиной рендера.

### `handleAdd`

Функция является координатором, а не местом валидации. Она получает результат `addShoppingItem`, различает неуспех и успех, затем обновляет UI-состояние. Ранний `return` гарантирует, что ошибка не расходует `id` и не очищает введённую строку.

### `handleClear`

Функция заменяет список результатом чистой функции и очищает ошибку. Она не знает, сколько элементов было в массиве: поведение одинаково для пустого и непустого списка.

### Условный рендеринг

Выражение `items.length === 0 ? ... : ...` гарантирует взаимоисключающие состояния: пользователь видит либо `No items yet.`, либо `FlatList`.

### Чистые функции

Функции из `src/shopping-list.js` детерминированы относительно аргументов и не имеют побочных эффектов. Это упрощает тестирование краевых случаев без запуска мобильного интерфейса.

### Стили

Внешний контейнер занимает экран, а `screen` ограничивает ширину значением `420`. Карточки имеют белый фон, рамку и скругление. Поле получает явную рамку, ошибка — тёмно-красный цвет, элементы списка — светло-синий фон. `buttonCell: { flex: 1 }` делит строку кнопок поровну.

## 9. Управляемая практика

Преподаватель задаёт задачу, ученица прогнозирует результат и только затем проверяет его.

### Практика A. Трассировка успешного добавления

Исходное состояние: `items = []`, `itemInput = '  Milk  '`, `errorMessage = ''`, `nextItemIdRef.current = 1`.

Ученица заполняет результат:

- `addition` → `{ ok: true, items: [{ id: 'item-1', name: 'Milk' }] }`;
- `nextItemIdRef.current` → `2`;
- `items` после setter → массив с `Milk`;
- `itemInput` → `''`;
- `errorMessage` → `''`.

Подсказка преподавателя при затруднении: «Отдели локальный объект `addition` от состояний компонента».

### Практика B. Трассировка ошибки

Исходное состояние: один элемент `Bread`, `itemInput = '   '`, следующий номер `2`.

Ожидается:

- `addition` → `{ ok: false, error: 'Enter an item name.' }`;
- `items` остаётся без изменений;
- `itemInput` остаётся `'   '`;
- `nextItemIdRef.current` остаётся `2`;
- `errorMessage` становится `Enter an item name.`.

### Практика C. Дубликаты и ключи

Ученица добавляет `Milk`, `Bread`, `Milk` и объясняет два массива:

```js
items.map((item) => item.name) // ['Milk', 'Bread', 'Milk']
items.map((item) => item.id)   // ['item-1', 'item-2', 'item-3']
```

Контрольный вопрос: «Почему первое отображение содержит повтор, а второе — нет?» Ожидается: имя — пользовательские данные и может повторяться; `id` — техническая идентичность.

## 12. Вопросы преподавателя и полные ответы

### 1. Почему `TextInput` называется управляемым?

Его отображаемое значение поступает из `itemInput` через `value={itemInput}`, а каждое пользовательское изменение передаётся в `setItemInput` через `onChangeText`. Источником истины является React state, а не внутреннее значение нативного поля.

### 2. Почему недостаточно проверить `if (text === '')`?

Строка из пробелов не равна пустой строке. После `trim()` внешние пробелы удаляются, и строка `'   '` превращается в `''`; только тогда проверка правильно отклоняет визуально пустой ввод.

### 3. Почему `normalizeItemName` возвращает объект с `ok`?

Единый признак `ok` делает две ветви явными. При успехе вызывающий код получает `name`, при ошибке — `error`. `handleAdd` сначала проверяет `ok`, поэтому не пытается использовать отсутствующее поле `items`.

### 4. Почему `addShoppingItem` не вызывает `setItems` сама?

Это чистая функция предметной логики: она не зависит от React и возвращает результат. Владелец состояния — компонент `App`, поэтому только он решает, когда вызвать setter. Такое разделение упрощает повторное использование и unit-тестирование.

### 5. Почему используется `[...items, newItem]`, а не `items.push(newItem)`?

`push` меняет существующий массив и возвращает его новую длину. Spread создаёт новую ссылку массива, сохраняя исходный массив. React получает явное новое значение состояния, а тест может подтвердить отсутствие мутации.

### 6. Почему `nextItemIdRef` — ссылка, а не state?

Номер нужен между рендерами, но сам по себе не отображается. Изменение `.current` не должно создавать отдельный рендер. Новый рендер всё равно произойдёт после `setItems` при успешном добавлении.

### 7. Почему обычная локальная переменная `let nextId = 1` не подходит?

Тело функционального компонента выполняется при каждом рендере, поэтому локальная переменная снова стала бы равной `1`. `useRef` сохраняет объект ссылки между рендерами текущего монтирования.

### 8. Почему счётчик увеличивается после проверки `addition.ok`?

Неуспешный ввод не создаёт элемент и не должен расходовать идентификатор. Поэтому после ошибки следующий успешный товар получает ожидаемый очередной номер.

### 9. Почему `item.name` нельзя использовать как ключ?

Условие разрешает одинаковые названия. Два товара `Milk` получили бы один ключ, и React не смог бы однозначно различать сущности. `item.id` уникален и сохраняется у объекта.

### 10. Почему индекс массива не лучший ключ?

Индекс описывает положение, а не сущность. При вставках, удалениях или сортировке положение меняется, и React может сопоставить состояние строки не тому элементу. В текущей модели уже есть стабильный `id`, поэтому индекс не нужен.

### 11. Что получает `renderItem`?

`FlatList` вызывает функцию с объектом параметров. Деструктуризация `({ item })` извлекает текущий элемент, после чего JSX возвращает `Text` с `{item.name}`.

### 12. Зачем пустое состояние выводится отдельно?

Пустой `FlatList` без пояснения может выглядеть как ошибка или незагруженный экран. Текст `No items yet.` сообщает, что список корректно пуст и ожидает действия пользователя.

### 13. Что именно очищает `handleClear`?

Он устанавливает новый пустой массив в `items` и пустую строку в `errorMessage`. Он не вызывает `setItemInput` и не меняет `nextItemIdRef.current`, поэтому поле и следующий номер сохраняются в текущем монтировании.

### 14. Что произойдёт после полного перезапуска приложения?

Компонент монтируется заново, все `useState` получают начальные значения, а `useRef` снова получает `1`. Постоянного хранилища нет, поэтому прежний список исчезает.

### 15. Чем unit-тест чистой функции отличается от UI-теста?

Unit-тест напрямую вызывает `normalizeItemName`, `addShoppingItem`, `getShoppingItemKey` и `clearShoppingItems`, быстро проверяя вход и выход. UI-тест рендерит `App`, создаёт события ввода и нажатия, затем проверяет props и видимый текст. Вместе они покрывают логику и её соединение с интерфейсом.

### 16. Зачем `accessibilityLiveRegion="polite"`?

На Android это сообщает сервису доступности, что изменившийся текст нужно объявить, когда это не прервёт более важную речь. Для ошибки формы это более бережное поведение, чем агрессивное прерывание.

### 17. Почему у текста ошибки нет `accessibilityLabel`?

Если задать постоянную метку, она может заменить фактическое содержимое для сервиса доступности. Здесь важна конкретная ошибка `Enter an item name.`, поэтому используется сам текст. Тест закрепляет отсутствие переопределяющей метки.

### 18. Как доказать, что порядок сохраняется?

Новый объект добавляется в конец нового массива выражением `[...items, newItem]`, а `FlatList` получает этот массив без сортировки. UI-тест проверяет `['Milk', 'Bread', 'Milk']` в `shoppingList.props.data`.
