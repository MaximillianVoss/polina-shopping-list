# №15 — Shopping List с React Native Paper и SQLite

Готовое приложение продолжает логику №11: продукт, количество, добавление и удаление по ID, локальная база `shopping.db`, таблица `shopping`. Интерфейс реализован компонентами React Native Paper.

Путь работы: прочитать [условие](ASSIGNMENT.md) → установить зависимости → запустить → выполнить сценарии проверки → разобрать [полный мануал](MANUAL.md).

## Запуск

Нужен Node.js 24.x. В терминале откройте именно эту папку проекта:

```bash
npm ci
npm run typecheck
npm test
npm start
```

В Expo нажмите `i` для iOS Simulator на Mac, `a` для Android Emulator или `w` для браузера. Для браузера можно сразу выполнить `npm run web`.

Android/iOS сохраняют данные в SQLite через `expo-sqlite`. Web — отдельный просмотр с `localStorage`; данные браузера и телефона не синхронизируются.

## Проверка

Добавьте Tomatoes / 5 kg, Eggs / 6 pcs и Milk / 2 litres; удалите Eggs значком корзины. Перезапустите приложение: Tomatoes и Milk должны остаться. Пустые поля не должны создавать запись.

```bash
npm run typecheck
npm test
npx expo export --platform android --platform web --output-dir dist
```

SQL-тесты используют настоящий SQLite из Node.js 24. Проверка на Windows включает типы, запросы, сохранение файла и сборки Android/Web; запуск на iPhone, Android-устройстве и Mac требует отдельной проверки.

## Основа и совместимость

Это продолжение №11 с SQLite. Firebase из №12 и AsyncStorage не используются. Готовая отдельная папка настроена на Expo SDK 54. Существующий №11 в прежнем комплекте может использовать другой SDK: инструкция переноса исходников без замены его зависимостей приведена в мануале.

Одинаковая схема позволяет новому экрану читать старые записи в том же приложении. Запуск отдельного проекта с другим `slug` создаёт другое хранилище, поэтому база №11 не переносится автоматически.

`package-lock.json` входит в комплект и фиксирует установленные зависимости. Каталоги `node_modules`, `.expo`, `.verification` и сборки не нужны для передачи проекта.
